# 使用说明

服务器起来之后，日常只需要浏览器。本文说明能读什么、页面怎么用、书怎么组织、有哪些已知限制。

## 1. 支持哪些格式

| 格式 | 阅读方式 | 说明 |
|---|---|---|
| `.epub` | 网页内渲染（epub.js） | 按 OPF spine 分章，保留原书排版、图片、CSS |
| `.txt` | 整屏分页 | 自动探测编码（UTF-8 / GB18030 等），按行首正则识别章节生成目录 |
| `.mobi` | 纯文本分页 | 自研 PalmDOC 解压 + 记录级截断，抽取正文与目录 |
| `.azw3` / KF8 | 纯文本分页 | 自研 KF8 解析（解压重组 + NCX/ctoc 取真实章节标题） |
| `.pdf` | 浏览器/外部打开 | 不做重排，**不支持** DRM、Print Replica、HD 容器 |

文件名里带中文、空格、方括号都可以，入库时按原始路径索引。

## 2. 打开书库

```
http://<host>:<port>/
```

- 默认首页是**列表模式**（可切换到封面墙），标题、分类、进度一屏可见。
- 如果部署时设了 `BOOK_CODE`，首页会要一个访问码；它只是防止局域网里被随手翻看，不是加密。
- 外网访问请走 VPN/隧道（例如 Tailscale），不要把端口直接映射到公网。

## 3. 页面导航

| 位置 | 作用 |
|---|---|
| 首页 | 列表/封面墙切换、按分类浏览、搜索标题 |
| 阅读页 | 整屏翻页（TXT/分章）或 iframe 渲染（EPUB），顶部工具栏可调字号、字体、配色 |
| 阅读记录 / 进度 | 记住每本书读到哪，支持“继续上次” |
| `/stats` | 阅读统计：时长、册数、每日趋势 |
| 回收站 | 删除的书先进回收站，`BOOK_TRASH_DAYS` 天后自动清理 |

## 4. 书库怎么组织

只需要一个根目录（`BOOK_BASE`），**子目录名就是分类名**：

```
library/
├── 科幻/
│   ├── 三体.epub
│   └── ...
├── 历史/
│   └── ...
└── 待整理/
    └── 某本书.txt
```

- 新文件放进去后约 20 秒内自动入库，不用点“刷新”。
- 移动文件到别的分类会触发索引更新，进度不会因此归零（进度按书的路径键记录）。
- 同一本书重复文件不会自动合并，建议自己清理（存储分析里能看到重复项）。

## 5. 阅读体验

- **TXT 是整屏翻页，不是滚动**：按页面真实可视高度测量，段落放不下时按字符续排，不会出现半截句子。
- **字体**：内置霞鹜文楷子集（`static/fonts/`），启动时等字体就绪再分页，避免用回退字体度量导致错位。字体到达后会自动重排。
- **配色三档**：白底、浅绿、深灰。深灰档同时作用于阅读页与界面。
- **进度条与百分比**：按章节 + 章内位置换算，切字号/换设备后位置仍能对上。

## 6. 多设备进度同步

同一个书库被多台设备访问时，进度以服务端为唯一真相：

- 客户端每 30 秒轮询一次；发现别处有新进度且百分比差 ≥2% 时，底部弹“其他设备已读到 X%，点此跳转”。**点了才跳**，不打断当前阅读。
- 旧页面迟到回写会被识别并拒绝（服务端时间戳单调递增 + 位置前进判定），返回 `stale:true`，只累计阅读时长、不改位置。
- 进度落盘 12 秒一次，兼顾 SD 卡寿命与换设备时的新鲜度。

## 7. 接到别的阅读器

| 方式 | 地址 | 用途 |
|---|---|---|
| OPDS | `http://<host>:<port>/opds` | 静读天下、KyBook、FBReader 等可以直接挂载浏览/下载 |
| Legado 书源 | `http://<host>:<port>/api/legado` | 「阅读」App 的书源接口（原生 JSON + JSONPath，不依赖 JS 引擎） |

OPDS 客户端填地址时注意**结尾不要多写斜杠**，尾部斜杠会导致相对链接拼接错位返回 404。

## 8. 浏览器侧能力

- **PWA**：可以添加到主屏、全屏无地址栏。完整的离线缓存需要 HTTPS（浏览器限制），纯 `http://<IP>` 下只能部分生效。
- **TTS 朗读**：用浏览器自带语音引擎，文字量大的章节建议分页朗读。
- **PNA 限制**：从公网页面去加载私网图片/子资源会被 Chrome 拦（正文空白但封面正常）。解决办法是用 HTTPS 域名访问，而不是裸 IP。

## 9. 已知限制

- 不做 DRM 解密；不做 PDF 重排；不做 Print Replica / HD 容器（AZW4）。
- EPUB3 的 `nav.xhtml` 目录未解析，走 spine 兜底（章节顺序正确，标题层级可能不如原书细）。
- 索引库是单文件 SQLite，多台机器共享同一个 `data/books.db` 不安全，不要放网络盘上让两台服务同时写。
- 一次只处理一本书的解析任务，超大书（几十 MB 的 EPUB/MOBI）首次入库会占几十秒到几分钟，期间页面仍可用。
